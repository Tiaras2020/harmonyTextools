# CLI 工程范围与后台操作（1.0.28）

## 行为

- 构建前检查、`documents.list`、`project.refresh` 使用同一授权工程缓冲区范围。工程外未保存文件、无路径的新建缓冲区不阻止当前工程构建；不替用户保存它们。
- 工程内未保存或冲突仍拒绝构建，返回 `error: unsaved_edits` 和 `blockers` 数组，包含相对路径、modified、conflict、exists、master。即使磁盘文件已删除，仍列出对应缓冲区。排队后出现编辑的失败任务也通过 `job.status.blockers` 返回详情。
- 第一个通过认证的 CLI 请求到达后，会话面板自动隐藏，授权与服务器继续有效。左侧 CLI 自动化页显示状态，通过“打开 CLI 会话…”重新打开；“关闭会话”撤销授权。这里的“已连接”表示会话曾收到认证请求，不表示客户端持有永久 TCP 连接。
- CLI 打开文档、设置主文件、构建不会主动 raise/activate/show 主窗口或强制编辑器焦点；CLI 编译启动错误通过任务输出报告，不弹阻塞提示框。用户手动打开文件的原有行为保留。
- 19 个命令、连接协议和 `ok` 语义保持不变；连接文件及离线帮助同步说明新行为。

## 验证范围

主机检查：授权目录边界、无路径文档排除、缺失文件可见、任务阻塞信息、内容刷新、原子替换、删除/重建、最终轮诊断和旧失败缓存提示；19 个帮助主题与应用内清单一致。

平板限定用例：保留工程外未保存编辑，授权工程尚无打开文件，首次直接构建成功；连续打开、主文件切换、失败构建、失败后重建通过。构建期间采样 WindowManagerService 焦点，浏览器持续保持前台。工程内未保存编辑阻止构建并给出对应路径；随后删除该测试文件，缓冲区仍出现在列表及 blockers 中。自动收起、侧栏恢复与关闭会话状态另经界面核对。

证据目录：`validation/background-cli-1.0.28/`。最初候选完成行为回归，随后仅把不存在的侧栏图标资源 `log` 改为实际存在的 `logpanel`，重新签名安装；最终包额外核对侧栏。最终结果以 `device-result.json` 为准。

这不是后台保活服务：应用仍须运行，鸿蒙系统的休眠、后台冻结或终止不在本次保证范围内。CLI 的目录授权约束接口访问，不是 TeX/Lua 运行沙箱；编译仍使用磁盘依赖。此次没有重测全部引擎和宏包兼容性，运行包保持 1.0.21。
