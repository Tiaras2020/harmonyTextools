# 资源分层、命令行与分发方案

核对日期：2026-09-16。当前 B2.4 已交付 1.0.14 公共 HNP 完整版，新增 Beamer、PGFPlots、newpx 和 BibTeX 真机验收。2025.2 开发包采用 runtime-extension-v2；当前交付见 `COMMON-RESOURCES-B24.md`。B2.3 双版本历史证据见 `FULL-RESOURCES.md`；以下保留分层设计与阶段背景。

## 1. 集成 TeX Live 是否等于所有终端都能编译

项目集成了 TeXstudio、移植到鸿蒙的原生 TeX 引擎，以及选取的 TeX Live 资源，并非桌面 TeX Live 全量移植。

当前 `module.json5` 把 texlive.hnp 声明为 public，提供 pdflatex、xelatex、bibtex 等入口。OpenHarmony 的公有 HNP 机制支持其他应用访问原生程序，但应用仍需具备对应运行环境；这不等于任意终端自动成为完整 TeX 环境。

当前 TeXstudio 在启动编译子进程时设置 TEXMFCNF、TEXINPUTS、TEXMFDBS、FONTCONFIG_FILE、ICU_DATA 等变量。导入资源在本应用的 filesDir 中，其他终端应用不能把自己的同名沙箱路径当成本应用的目录。只设置 PATH 不能解决资源授权、字体和动态库环境问题。

2026-09-16 用户明确反馈：真机 HiShell 中 `pdftex` 和 `xelatex` 可用。记录为用户真机验证，不能再把“外部终端不支持”作为当前结论。此前 hdc shell 中 `command -v pdflatex` 未找到命令、直接调用物理 HNP 入口返回 Permission denied，只描述该调试 shell 的环境，不能外推到 HiShell。

B2.1 已在 HiShell 实测公共 HNP 命令和内置资源可用；应用私有宏包不会自动进入终端搜索路径。导出用户备份、在授权下载目录解压、设置 TEXINPUTS 后，pdfTeX 和 XeLaTeX 均成功读取修改的宏包并生成 PDF。具体命令和边界见 USER-RESOURCES.md；无需先实现应用内命令面板。

官方机制依据：https://github.com/openharmony/startup_appspawn/blob/master/service/hnp/README_zh.md

## 2. ZIP 的生命周期

导入时解压到应用持久目录，逐文件检查大小和 SHA256，生成 ls-R 后提交为一个资源版本。编译读取解压后的文件，不依赖原 ZIP。成功导入后原 ZIP 可以移走或删除，保留它只为备份。

导入期间需要同时容纳原 ZIP、解压暂存文件和已有资源；暂存目录在完成时改名提交，不会另复制一整份解压内容。应用卸载/清除数据会影响私有资源，备份应导出到应用目录之外。

## 3. 完整资源的边界

资源完整度：可逐步覆盖固定 TeX Live 年份中的宏包、模板、语言数据及字体，文档和源码可分开选装。程序完整度：Perl/latexmk、Biber、LuaHBTeX、Python/Pygments、Ghostscript 等需要分别移植、签名和验收，仅复制其宏包或脚本不能保证相关功能运行。

当前 additive-v1 仅是附加资源协议：基础资源优先、一个启用集合、8 GiB 解压上限、有限文件类型；不允许替换内核/格式，尚不支持 Type1 映射和任意 Lua 模块。不能直接把完整 texmf-dist ZIP 丢进来就称为完整版。B2 需要依赖解析、文件类型支持、映射生成、兼容配置及实际容量预检。

完整桌面 TeX Live 是数 GB 级，包含文档/源码时可更大；鸿蒙资源包的准确大小应从固定年份清单计算，不能拿桌面安装器示例数字作本项目承诺。

## 4. 两种分发方式和用户编辑

| 方案 | 可行性 | 代价 |
| --- | --- | --- |
| 完整资源随本体发布 | 构建层面可以选择完整资源树打入 HNP | 安装包与更新大；仍需核对实际分发渠道限制 |
| 基础本体 + 外部完整资源包 | 可以共用引擎与资源管理代码 | 首次导入需要空间和时间，必须检查资源与引擎兼容性 |

用户最新选择：默认面向用户发布内置完整兼容运行资源的版本；开发构建保留“精简本体 + 外部资源包导入”以加快迭代。两者共用资源清单和兼容标识，另保留可编辑用户资源层。这里的“完整”指当前鸿蒙引擎和工具链能力范围内的完整运行资源，不表示整个桌面 TeX Live 工具链已经移植。

完整版必须在签名前把经过校验的发行资源合并到公共 texlive HNP 的 texmf 树，生成索引、字体映射及正确的默认搜索配置，随 HAP 一起安装。不能把完整 ZIP 塞入 HAP 后仅解压到应用私有 filesDir，否则 HiShell 仍不能直接使用。现有内置资源已能在 HiShell 中被公共 HNP 引擎发现；完整版的验收要求是在新终端中不手工设置 TEXINPUTS、不导出同步即可编译代表性项目。用户自己修改的私有资源仍按 B2.1 方式管理和同步。

开发版导入与完整版预装应来自同一份审核后的资源集合。安装后导入私有目录不会自动改变已签名的公共 HNP；若要把发行资源更新提供给 HiShell，当前方案是构建并安装新版完整版。

两种分发方式都应另设可编辑的用户资源层，允许用户新增或有意识地覆盖普通宏包，而不是直接改动受校验的发行资源。已实现查找顺序：项目目录 → 用户宏包层 → 选定发行资源；内核/格式等核心组件继续单独绑定兼容版本。需要提供冲突提示、禁用用户层、重建索引和备份恢复。

B2.1 已接入 texmf-home 和相应 TEXINPUTS、字体/BibTeX 搜索变量。用户层可编辑、添加、删除、启停、备份恢复；内置资源与附加包保持原有校验管理。

## B2.1 已实现范围与验收要求

本节为 B2.1 实现和验收范围，交付版本 1.0.11。详细证据和未验收边界见 USER-RESOURCES.md。

1. 核对 HiShell 中 pdftex/xelatex 的入口与资源搜索路径，以新增独有宏包为例分别验证两个应用的文件可见性。只检查工具链相关信息，不读取终端历史或无关项目。
2. 接入独立用户 texmf 树，普通宏包按“项目目录 → 用户层 → 当前发行资源”查找；发行资源与匹配内核/格式保持独立管理。不能仅调整一个 TEXMFHOME 变量，因为当前代码显式设置了 TEXINPUTS 等搜索路径。
3. 增加用户文件管理：导入文件、打开编辑、删除、导出备份、重建索引、禁用用户层。普通宏包改动应在下一次编译生效，无需为每次修改制作带 SHA256 的发行包；字体修改需要刷新相应缓存。
4. 对同名宏包显示覆盖来源与冲突提示；核心内核/格式组件不作为普通用户覆盖项。提供一键禁用用户层以定位问题，避免重装应用。
5. 真机验收：新增宏包、修改内容后输出改变、覆盖与禁用后回退、导出恢复，以及 HiShell 中对应的编译行为。若两个应用不能直接共用目录，明确提供同步流程，不能静默声称资源已共享。

B2.2 已完成固定 TeX Live 版本依赖解析、兼容资源集合、字体映射和容量检查。B2.3 已完成公共 HNP 完整版与精简开发导入包。B2.4 已按功能审核常用宏包并完成 BibTeX 项目回归；下一步优先 Perl/latexmk 自动多轮构建，再独立推进 Biber、LuaHBTeX 原生工具移植。文档/源码未随运行资源整体打包。

## B2.2 的兼容性筛选规则

2026-09-16 已实现第一批保守候选集合与宿主回归，详情见 `FULL-RESOURCES.md`。下列规则是持续审核要求，并不表示所有待审核包已经完成适配。

依赖解析只解决上游包之间的关系，不证明鸿蒙运行能力。构建时还需核对引擎、外部程序、脚本解释器、字体映射、格式/内核版本及安装生成步骤：

- 普通平台无关宏包、类文件、语言数据和字体：满足当前引擎/内核要求后纳入候选，按资源类型和代表性项目回归验收；字体映射等不能仅靠复制文件。
- 桌面平台二进制：不从 TeX Live 的 Windows/Linux/macOS 包中直接带入运行集合。只允许已移植、依赖闭合并按项目流程签名验收的鸿蒙程序。
- 依赖未移植解释器、外部工具或引擎的功能：列为条件可用或暂不支持；即使宏包文件可保留，也不能标成完整可用。按具体功能区分必需依赖和可选后端，不简单把整个宏包全部判为可用或不可用。
- 未知兼容性：进入待验证清单，不默认为已支持；核心资源升级须与格式和引擎一起验收，不能随上游依赖解析静默替换冻结基线。
- 输出纳入/排除/条件可用/待验证清单及原因。默认支持集合存在未满足的必需依赖时，构建失败或明确移出该功能的支持声明，不能只删依赖并把剩余包当作完整支持。

additive-v1 的文件类型/路径限制并未实现上述能力分析；B2.2 构建端解析器负责候选筛选。B2.3 已新增 runtime-extension-v1，支持审核后的字体和映射集合导入；公共 HNP 完整版已独立验收。未知兼容性仍须审核，不能凭文件类型判断所有功能支持。

## 5. 删除和导出

1.0.7 缺少删除和导出，恢复内置资源只是切换选择，不释放扩展资源占用。

1.0.8 新增导出所选资源、删除所选资源。导出保存原清单和声明文件，生成可重新导入的 ZIP，不导出生成的索引/缓存。删除仅针对未被当前会话使用、也未被下次启动选中的扩展版本，同时清理该版本缓存；应用内置资源不能通过此功能删除。

当前使用的包应先恢复内置资源或切换到其他版本，完整重启，再删除旧版本。导出不要求原始 ZIP 存在。发行包导出不包含应用程序，也不是任意用户修改文件的打包工具。
